# 经验与排错

## 1. 先看 `adb reverse`

设备重启、adb 重连、USB 拔插后 reverse 会丢失。典型现象：

- 客户端报“资源载入异常，请重试 错误号:1103”
- 客户端报“获取网络配置失败，请重新登录”
- logcat 出现 `Failed to connect to /127.0.0.1:8443 ... ECONNREFUSED`（旧方案为 8080）

处理：

```bash
adb -s <serial> reverse --list
adb -s <serial> reverse tcp:8443 tcp:8443
adb -s <serial> reverse tcp:8444 tcp:4443
adb -s <serial> shell settings put global http_proxy :0
```

## 2. `syncData` 必须与客户端本地状态一致

如果服务端返回的是旧存档（例如主线进度 0、没有干员），而客户端本地已经是通关状态，客户端会拒绝同步。迁移旧服务端时，应把旧库中 `account.user` 的完整 JSON 写入 `accounts.user_json`，不要只用初始模板覆盖。

## 3. SDK 信封格式

HGSDK 的 `NewApi` 解析逻辑：

```text
status / msg / data
data 是字符串时：直接 new JSONObject(data)
data 是对象时：getString(data) 得到 JSON 文本后再解析
```

桥接层对 `basic` / `grant` 使用 `sdk_wrap()` 统一包装；`grant` 返回的 `data` 至少需要 `code`、`token`、`uid`。

## 4. “同步身份信息失败（错误号 200）”

2026-11-22 首次修复：根因不是 `login` / `syncData` 接口失败，而是 `syncData` 返回的 `status.lastRefreshTs` 没有随 `lastOnlineTs` 一起刷新，客户端用旧时间做身份同步校验。

修复点：

```python
ts = now_ts()
status["lastOnlineTs"] = ts
status["lastRefreshTs"] = ts
```

2026-11-23 二次修复：错误号 200 也对应 HGSDK 的 `SDKCode.RESPONSE_ERROR`。反向代理模式下 `pretty_host` 是 `127.0.0.1`，不能再用原始域名判断 `basic` / `grant`；这两条 SDK 路由必须按 path 命中，并返回 `data` 为 JSON 字符串的信封。桥接层现在还会在 token 缺失或过期时用 `.env` 的 `ARK_TOKEN` 重试，避免 `basic` 返回没有 `data` 的 `status:1` 后被 SDK 解析成 200。

```bash
curl -sk 'https://127.0.0.1:4443/user/info/v1/basic?token=__stale__'
curl -sk -X POST 'https://127.0.0.1:4443/user/oauth2/v2/grant' \
  -H 'Content-Type: application/json' \
  -d '{"token":"__stale__","type":0,"appCode":"7318def77669979d"}'
```

两者都应返回 `status=0`，`data` 是字符串，且 `identityNum` / `uid` 为 `10000000`。

复现时先查：

- `request_logs` 中 login / syncData 是否 200；
- `syncData` 响应里 `status.lastOnlineTs` 与 `status.lastRefreshTs` 是否相等且为当前时间；
- 客户端是否仍在使用旧的本地缓存（必要时只备份/重置 SDK prefs，不要 `pm clear`）。

## 5. 资源接口

`network_config.hu` 指向本机时，缺失资源需要 302 回源：

```text
/assetbundle/official/{os}/assets/{hash}/{file}
  → https://ak.hycdn.cn/assetbundle/official/{os}/assets/{hash}/{file}
```

## 6. 客户端协议弹窗

- `network_config` 中 `devsdk` 必须是 `false`，不能是 `null`；
- `update_agreement` 返回 `{"status":0,"msg":"OK","type":"A"}`；
- `secure` 为 `false`；
- `hu`、`hv`、`gs`、`as`、`u8` 必须齐全。

## 7. 调试顺序

1. `curl /healthz`、`/general/v1/server_time`；
2. Web UI 登录；
3. `request_logs` 看客户端真实请求；
4. `logcat` 看 `GameUpdateSdk` / `HypergryphSDK` / `Unity`；
5. 最后再怀疑客户端缓存；先检查 reverse、proxy、后端进程。
