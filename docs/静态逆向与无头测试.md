# 静态逆向与无头测试

## 决策

自 2026-11-22 起，本项目默认使用「静态逆向 + 无头协议测试」推进，不再把 ADB 模拟点击与截图作为探索或验收手段。

```
静态协议提取 → 无头 pytest → 阶段末真机日志联调
```

- 截图只保留为历史证据，不参与判定。
- 接口是否有问题，以 HTTP 状态、`result/status`、响应结构、SQLite 状态变化为准。
- 真机只在每个阶段无头测试全绿后启动一次，验收看 `request_logs` 与 `adb logcat`。
- 客户端签名、加密和 Header 参数从客户端协议层还原，测试脚本不依赖 adb、Frida 或手工点击。

Web UI 的「研发状态」页（`/admin/development`）同步展示模式、门禁、逆向产物、协议矩阵和测试日志。

## 1. IL2CPP 提取

目标设备与包名：

```bash
SERIAL=8.162.0.198:30135
adb -s "$SERIAL" shell pm path com.hypergryph.arknights
adb -s "$SERIAL" shell "su -c 'ls -lh /data/app/com.hypergryph.arknights-*/lib/arm64'"
```

本机已保存：

```text
tmp/逆向分析/2026-11-22/libil2cpp.so
tmp/逆向分析/2026-11-21/apk/global-metadata.dat
tmp/逆向分析/2026-11-22/global-metadata.decrypted.dat
tmp/逆向分析/2026-11-22/dump-static7/dump.cs
tmp/逆向分析/2026-11-22/dump-static7/stringliteral.json
tmp/逆向分析/2026-11-22/dump-static7/script.json
backend/data/protocol_catalog.json
```

`libil2cpp.so` 约 211 MB；原始 `global-metadata.dat` 约 43 MB。原始 metadata 头为：

```text
94 43 72 12
```

不是标准 `AF 1B B1 FA`，因此不能直接交给原版 Il2CppDumper。先处理 metadata 保护，再做导出。

### metadata 解密顺序

1. root 读取运行中进程的 `/proc/<pid>/maps`、`/proc/<pid>/mem`，在匿名可读映射中扫描标准 magic；命中后按 metadata 长度 dump。
2. 若运行内存中没有标准头，使用 Frida 在 `il2cpp_init` 前后定位 metadata 指针，或对 `libil2cpp.so` 的 metadata loader 做静态定位，还原解密函数和密钥。
3. dump 结果必须是标准 metadata；校验前 4 字节和文件长度后再进入 Il2CppDumper。
4. 导出 `dump.cs`、`stringliteral.json`、`script.json`、`il2cpp.h`。

本机 root 内存 dump 可直接执行：

```bash
/root/Knight/.venv/bin/python scripts/dump_metadata_memory.py \
  --serial 8.162.0.198:30135 --pid <游戏PID> \
  --output tmp/逆向分析/2026-11-22/global-metadata.decrypted.dat
```

脚本优先选择大小在 35–60 MB 的 `/dev/zero (deleted)` 映射；如果 PID 已变或映射地址变化，用 `--map-start 0x...` 指定 `/proc/<pid>/maps` 中的地址。

### 当前结果（2026-11-22）

- 运行进程的 metadata 映射位于 `/dev/zero (deleted)`，已通过 `/proc/19858/mem` 完整 dump；文件头补回标准 v29 `AF 1B B1 FA` 后，`global-metadata.decrypted.dat` 被 Il2CppDumper 识别为 `Metadata Version: 29`。
- 已生成 `protocol_catalog.json`：从 string literal 表解析出 **507 个后端路由**，全量 **50,548 个类型**，**7,197 个协议相关类型**；其中 **1,561 个 Request/Response 类型**已展开字段和方法参数名。
- 已用运行时地址 `CodeRegistration=0x77bef57ef8`、`MetadataRegistration=0x77bf2d9c50` 对应的 RVA（`0xc516ef8`、`0xc898c50`）完成导出。Hypergryph v29 的 `Il2CppTypeDefinition` 比上游多一个 `int32`（92 字节），并且 31 个 codegen module 名称指针被混淆；dumper 已补丁支持这两点，并对混淆模块按 metadata 方法数/顺序建立别名。
- 导出结果：`dump.cs` 79.4 MB / 2,268,336 行 / 50,548 个类型；`script.json` 413,106 个方法、559,981 个地址；`stringliteral.json` 37,294 条有效字符串。`dump.cs` 无错误块。
- 协议 catalog 已回填 1,500 个 Request/Response 类型的字段偏移与方法 RVA；Web UI 的「协议索引」页新增全量 `dump.cs` 搜索、原始片段和下载入口。
- 无头协议测试当前 23/23 通过；Web UI 的研发状态页显示门禁为 4/5（工件、metadata、dump、无头测试已通过，真机日志门禁待阶段末执行）。

注意：`dump.cs` 给出类型、字段和方法签名；路由字符串主要从 `stringliteral.json` 和程序集字符串提取；方法体逻辑要结合 `script.json` 地址做 Ghidra/objdump 反编译。

### dump 生成命令（2026-11-22 实跑）

运行中的注册地址是 `CodeRegistration=0x77bef57ef8`、`MetadataRegistration=0x77bf2d9c50`；按 `libil2cpp` 基址 `0x77b2a41000` 换成 RVA 后手动输入即可。`ForceDump` 必须关闭，否则会走内存 dump 的 pointer 修复路径，和这份静态 RVA 数据不匹配。

```bash
cd tmp/逆向分析/tools/Il2CppDumper-6.7.46
/root/.dotnet/dotnet build Il2CppDumper/Il2CppDumper.csproj \
  -c Release -o /root/mingrifangzhouyun/tmp/逆向分析/tools/Il2CppDumper-build

mkdir -p /root/mingrifangzhouyun/tmp/逆向分析/2026-11-22/dump-static7
cd /root/mingrifangzhouyun/tmp/逆向分析/2026-11-22/dump-static7
printf 'c516ef8\nc898c50\n' | /root/.dotnet/dotnet \
  /root/mingrifangzhouyun/tmp/逆向分析/tools/Il2CppDumper-build/Il2CppDumper.dll \
  /root/mingrifangzhouyun/tmp/逆向分析/2026-11-22/libil2cpp.so \
  /root/mingrifangzhouyun/tmp/逆向分析/2026-11-22/global-metadata.decrypted.dat .
```

补丁要点：

- `Il2CppTypeDefinition` 在 Hypergryph v29 中是 92 字节，比上游多一个 `int32`（位于 `interfaceOffsetsStart` 后、8 个 `uint16` 计数前）。
- 31 个 `Il2CppCodeGenModule.moduleName` 指针被混淆；按 metadata 每个 image 的 `method_count` 匹配，剩余同值组按相对顺序建立别名。`Assembly-CSharp.dll` 对应 codegen module `1`（225,450 个方法）。
- 上游 v29 的 `stringliteral.json` 会混入 metadata 原始字；用 `scripts/export_il2cpp_string_literals.py` 从 literal 表重新导出。
- 用 `scripts/enrich_protocol_catalog_from_dump.py` 把字段偏移、方法 RVA 和签名回填到 `backend/data/protocol_catalog.json`。

## 2. 无头协议测试

测试目录：

```text
tests/protocol/
  conftest.py
  test_sdk_login.py
  test_account_sync.py
  test_battle.py
  test_admin.py
```

运行：

```bash
cd /root/mingrifangzhouyun
/root/Knight/.venv/bin/python -m pytest tests/protocol -q \
  --junitxml=logs/protocol-junit.xml
```

测试账号在运行时通过 SDK 手机号流程新建，使用独立 token，结束后从 SQLite 清理。测试覆盖：

- SDK 配置、服务器时间、网络配置；
- basic、OAuth grant、U8 getToken、商品列表；
- `account/login`、`syncData`、`syncStatus`；
- `lastOnlineTs` / `lastRefreshTs` 同时刷新并持久化到 SQLite；
- `battleStart` / `battleFinish`、未知路由空 delta；
- 管理后台登录与研发状态页。

Web UI 的「运行无头协议测试」按钮会异步执行同一套 pytest，并刷新 JUnit 结果。

生成静态协议索引：

```bash

  tmp/逆向分析/2026-11-22/global-metadata.decrypted.dat \
```
