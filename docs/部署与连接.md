# 部署与连接

## 1. 准备

```bash
cd /root/mingrifangzhouyun
cp .env.example .env
```

编辑 `.env`：

- `MYSQL_ROOT_PASSWORD` / `MYSQL_PASSWORD`：改成自己的密码；
- `ADB_SERIAL`：`adb devices` 里的设备序列号；
- `ARK_PHONE` / `ARK_TOKEN` / `ARK_UID`：本地账号信息，默认即可；
- `SERVER_URL`：默认 `http://127.0.0.1:8443`，配合 `adb reverse` 使用。

## 2. 启动 MySQL 8.4

```bash
docker compose up -d
docker ps --filter name=arkmysql
```

首次启动会初始化数据库和 `ark` 用户。MySQL 只发布到 `127.0.0.1:3306`。

## 3. 启动 Java 后端

```bash
./server/start.sh
```

脚本会用 `.env` 生成 `server/config.json`，然后启动 `hypergryph.jar`。看到以下日志即成功：

```
Tomcat started on port(s): 36650 (http) 8443 (http)
数据库版本 8.4.x
启动完成!
```

建议用 systemd 或 `nohup setsid ./server/start.sh > server/server.log 2>&1 &` 常驻。

## 4. 初始化账号

```bash
./scripts/seed_account.sh
```

脚本会：

- 在 MySQL 中插入/更新 `account` 行（token=`lab_manual_token`）；
- 把 `HypergryphSdkPreferences.xml` 写入设备，令客户端直接使用该 token。

如果设备没有 root，脚本会跳过设备写入；此时可以手动在游戏登录界面用“手机号+验证码”走桥接层的 mock 登录（任意 6 位验证码）。

## 5. 连接设备

```bash
./scripts/connect_device.sh
```

它会设置：

```
adb reverse tcp:8080 tcp:8080
adb reverse tcp:8443 tcp:8443
settings put global http_proxy 127.0.0.1:8080
```

### 5.1 安装 mitmproxy 系统 CA

Android 7+ 默认不信任用户 CA。需要把 mitmproxy CA 安装为系统 CA：

```bash
ls ~/.mitmproxy/mitmproxy-ca-cert.pem
HASH=$(openssl x509 -inform PEM -subject_hash_old -in ~/.mitmproxy/mitmproxy-ca-cert.pem | head -1)
cp ~/.mitmproxy/mitmproxy-ca-cert.pem ${HASH}.0
adb -s "$ADB_SERIAL" push ${HASH}.0 /data/local/tmp/
adb -s "$ADB_SERIAL" shell su -c "mkdir -p /data/local/tmp/cacerts; cp /data/local/tmp/${HASH}.0 /data/local/tmp/cacerts/; chmod 644 /data/local/tmp/cacerts/${HASH}.0; chcon u:object_r:system_file:s0 /data/local/tmp/cacerts/${HASH}.0"
```

然后用 root 把 `/data/local/tmp/cacerts` bind mount 到 `/system/etc/security/cacerts`（不同设备/内核方式不同；本环境已验证可用）。重启后 `adb shell ls /system/etc/security/cacerts/${HASH}.0` 应存在。

## 6. 启动游戏

```bash
adb -s "$ADB_SERIAL" shell am force-stop com.hypergryph.arknights
adb -s "$ADB_SERIAL" shell monkey -p com.hypergryph.arknights -c android.intent.category.LAUNCHER 1
```

标题页点击“开始唤醒”。首次会出现语音包选择：

1. 点“使用中文配音”卡片；
2. 点“确认”；
3. 回到标题页后再次点“开始唤醒”。

客户端会依次请求：`/app/v1/config` → `/user/info/v1/basic` → `/user/oauth2/v2/grant` → `/u8/user/v1/getToken` → `/account/login` → `/account/syncData`，然后进入教学剧情和 `guide_01` 战斗。

## 7. 常见问题

### 7.1 “网络配置解析失败，请重试”

原因通常是 `network_config` 中：

- `devsdk` 为 `null`（必须是 `false`）；
- 仍含 `{server}` 占位符（必须在返回前替换）；
- 缺少 `gs/as/u8/hu/hv` 字段。

检查：

```bash
curl -s http://127.0.0.1:8443/api/remote_config/1/prod/default/Android/network_config | jq .
```

### 7.2 登录后黑屏/回到标题

先看后端日志是否出现：

```
/account/login ... Status: 200
/account/syncData ... Status: 200
/quest/battleStart ... Status: 200
```

若只有 login/syncData，没有 battleStart，检查：

- `account.user.status.nickName` 是否为空；用 `scripts/seed_account.sh` 后手动更新为 `博士`；
- `account.user.status.uid` 是否为 `10000000`；
- 客户端是否在播开场视频（按一次返回键可跳过）；
- 是否卡在语音包选择（必须点确认）。

### 7.3 只看到 CONNECT 报文 / HTTPS 解密失败

系统 CA 未生效，或客户端使用了证书绑定。当前 2.7.91 的 SDK 请求走系统代理；游戏流量通过 `secure:false` 走明文 HTTP 到 8443，不需要为 `ak-gs-gf` 做 TLS 解密。

### 7.4 `adb push` 大文件卡住

本环境 ADB 链路对大于约 500 KB 的 push 不稳定。`seed_account.sh` 只推送几 KB 的 XML；游戏 APK、frida-server 等大文件建议走分块或 HTTP 下载。

### 7.5 输入坐标

设备逻辑分辨率是 1280x720，`adb shell input tap x y` 使用逻辑坐标。语音包选择：选卡 `(640,235)`，确认 `(640,475)`；开始唤醒 `(640,511)`。

## 8. 停止与清理

```bash
./scripts/stop_all.sh
```

脚本会停止 mitmdump、Java 后端，并撤销 `adb reverse` 与系统代理。MySQL 容器默认保留数据；如需彻底清理：

```bash
docker compose down -v
```
