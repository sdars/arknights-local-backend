# 面具模块接入官方客户端

## 结论

可以。当前实现是一个 Magisk / KernelSU / APatch 兼容模块 `ark-local`：它不改 APK，
用 systemless hosts、系统信任库、设备侧 relay 和 app UID 路由，把官方客户端引到本机后端。

已在设备 `8.162.0.198:30135` 上验证：官方 `com.hypergryph.arknights` 2.7.91 原包未改动，
启动后依次请求本机 `/user/info/v1/basic`、`/user/oauth2/v2/grant`、`/u8/user/v1/getToken`、
`/u8/pay/getAllProductList`、`/account/login`、`/account/syncData`，全部 200，并进入主界面。

## 链路

```text
官方 APK（不修改）
  │  ak-conf / as / game-config / launcher / ak-webview
  ▼
systemless hosts → 127.0.0.1
  ▼
设备 443 → nc relay → 127.0.0.1:8444
  ▼ adb reverse tcp:8444 -> tcp:4443
主机 mitmdump reverse:127.0.0.1:8443（系统 CA 信任）
  ▼
FastAPI 后端 8443

游戏 API 127.0.0.1:8443 → adb reverse tcp:8443 -> tcp:8443 → FastAPI
```

模块只做系统层重定向；客户端进程没有注入、没有改包、没有改 dex/so。

## 模块内容

- `deploy/magisk/ark-local/system/etc/hosts`：官方 SDK / 配置 / 启动器域名指向 `127.0.0.1`。
- `system/etc/security/cacerts`：构建时从主机 `~/.mitmproxy/mitmproxy-ca-cert.pem` 注入
  mitmproxy CA，开机后以 `system_file` 上下文挂载到系统信任库。
- `post-fs-data.sh`：启动早期挂载 hosts 和 CA；把 hosts 设为 `system_file`，解决 netd
  读取 `/data/local/tmp/hosts.ark` 时的 SELinux 拒绝。
- `service.sh`：启动 `443 -> 127.0.0.1:8444` relay；按游戏 UID 维护 `ARK_LOCAL` nat 链；
  关闭系统 HTTP 代理；每 15 秒复核一次；写 `/data/adb/ark-local/status`。
- `scripts/build_ark_module.sh`：计算 Android CA hash 并打包 zip。
- `scripts/install_ark_module.sh`：构建、推送、安装；APatch 默认走目录安装，避免
  `apd module install` 在异常 `/proc/mounts` 上阻塞；`--activate` 立即执行 hooks。
- `scripts/ark_module_status.sh`：查看模块状态、relay、nat 链、hosts、CA 与 adb reverse。

## 安装

```bash
./scripts/build_ark_module.sh
ADB_SERIAL=8.162.0.198:30135 ./scripts/install_ark_module.sh --activate
```

正式开机时模块的 `post-fs-data.sh` / `service.sh` 也会由 root 管理器执行。
主机侧 `adb reverse` 仍由 `scripts/watchdog.sh` / `ark-watchdog.service` 维持：
ADB reverse 的方向是从主机到设备，设备端模块无法自行创建。

## 注意

- 需要 root 和模块管理器；未 root 的设备无法用这种方式做系统级 hosts/CA。
- 模块不改变 `force_update`。如果后端同步了更高的客户端版本，旧 APK 仍会按现有登录校验处理。
- hosts 文件必须保持 `system_file` 上下文；主机 watchdog 已改为优先绑定模块的 hosts，
  不再重复叠加 `/data/local/tmp/hosts.ark`。
