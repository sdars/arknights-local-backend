### 4.1 同步身份信息失败（错误号 200）— 已修复

现象：登录后 U8/HG SDK 弹出“同步身份信息失败，请重试 / 错误号200”，但 `/account/login` 与 `/account/syncData` 均为 200。

修复：`backend/app/routers/game.py` 中 `sync_data` 同时写入 `lastOnlineTs` 和 `lastRefreshTs`，并复用同一个 `ts`。

2026-11-22 复测：客户端从标题页点击“开始唤醒”，进度 60% → 进入“累计签到活动”页面，未再出现 200 弹窗。后端 `request_logs` 显示 `basic → grant → getToken → getAllProductList → login → syncData → syncStatus` 全部 200。

#### 2026-11-23 二次复现与修复

现象：客户端停在标题页前的弹窗：`同步身份信息失败，请重试 / 错误号200`。后端 `/user/info/v1/basic`、`/user/oauth2/v2/grant`、`/account/login`、`/account/syncData` 均为 200；关闭弹窗回到标题页后重新点击“开始唤醒”可以进入签到页，说明问题在 SDK 身份信封与本地缓存 token 的组合路径。

根因：

- `ark-mitm` 是 reverse 模式，`flow.request.pretty_host` 已被改写为 `127.0.0.1:8443`，原先按 `as.hypergryph.com` 判断的 `basic` / `grant` 分支不会命中，响应没有稳定进入 HGSDK 信封；
- HGSDK 的 `BasicApiHandler` / `GrantApiHandler` 在数据缺失、token 为空或上游返回非零状态时会向上抛 `SDKCode.RESPONSE_ERROR = 200`；这正是界面上的“错误号200”；
- 本地缓存 token 与当前 SQLite 账号首次不同步时，`basic` 会返回 `status:1` 且没有 `data`，SDK 解析该响应即触发 200。

修复：`bridge/local_redirect.py` 改为按路径识别 SDK 路由，不再依赖 reverse 模式下的 Host；`basic` / `grant` 统一返回 `data` 为 JSON 字符串的 HGSDK 信封。请求 token 过期或缺失时，桥接层自动用 `.env` 中配置的本地 token 重试，并把 grant 的 `code/token/uid` 固定到本机账号。Web UI 研发状态新增“SDK 信封”和“过期 Token 自愈”两项探测。
