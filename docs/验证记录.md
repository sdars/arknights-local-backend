## 4. 关键修复记录

1. `network_config` 的 `devsdk` 从 `null` 改为 `false`，解决“网络配置解析失败”；
2. `network` / `global_net` 中的 `{server}` 全部替换为 `http://127.0.0.1:8443`；
3. `version` 同时提供 `Android`、`Windows`、`ios`、`global_Android` 等键，匹配 jar 的版本检查；
4. 新账号 `user.status.nickName` 设为 `博士`、`uid` 设为 `10000000`，避免空昵称循环；
5. mitmproxy 桥接层把 `basic` 的 `data` 对象转成 JSON 字符串，匹配 SDK 的 `getString("data")` 解析；
6. grant 的 `code`/`token` 都使用账号 secret，保证 `/account/login` 能查到账号。

## 5. 联调中遇到的两个关键问题

### 5.1 重复账号行导致 `/u8/user/v1/getToken` 返回“无法查询到此账户”

`seed_account.sh` 早期版本没有唯一索引，重复执行会插入多行相同 `secret`。后端的
`queryAccountBySecret` 在结果数不等于 1 时直接拒绝，客户端因此反复请求 `getToken`，
表现为 10% 连接界面卡住/回到标题。

修复：

- 清理重复行，只保留最小 `uid`；
- 给 `account.phone`、`account.secret` 增加唯一索引；
- `seed_account.sh` 改为“先删除同 secret 的重复行，再 insert-if-not-exists，最后 update 手机号/密码”。

### 5.2 协议更新弹窗反复出现

客户端在首次登录后调用 `POST /user/info/v1/update_agreement`。桥接层最初没有处理该路径，
请求落到官方服务器并失败，弹窗因此反复出现。

修复：桥接层直接返回：

```json
{"status":0,"msg":"OK","type":"A"}
```

之后点击“阅读并同意”即可关闭弹窗，继续 basic → grant → getToken → account/login → syncData。
